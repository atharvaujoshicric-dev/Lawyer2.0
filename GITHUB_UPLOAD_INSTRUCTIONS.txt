HOW TO DEPLOY TO GITHUB PAGES
==============================

STEP 1 — DELETE your current repo contents
  - Go to your Lawyer2.0 repo on GitHub
  - Delete ALL existing files (you can do this file by file, or
    use "..." menu → Delete this file for each one)

STEP 2 — UPLOAD these files
  The ONLY file GitHub Pages needs to serve your app is:
    index.html         <-- the entire app is inside this one file

  But also upload:
    .nojekyll          <-- tells GitHub to skip Jekyll processing
    README.md          <-- documentation (optional but useful)
    assets/            <-- source JS/CSS files for future editing
    partials/          <-- source HTML fragments for future editing
    database/          <-- SQL migration files for Supabase

  HOW TO UPLOAD FOLDERS:
  - Click "Add file" → "Upload files"
  - Drag the CONTENTS of each folder separately, not the folder itself
  - For assets/: drag everything inside assets/ → GitHub will ask
    for a folder path, type "assets"
  - Repeat for assets/css, assets/js, partials, partials/views,
    partials/modals, database, database/migrations, database/functions

  EASIER OPTION — use GitHub Desktop app or git command line:
    git clone https://github.com/atharvaujoshicric-dev/Lawyer2.0
    cd Lawyer2.0
    # copy all files from this zip into the folder
    git add .
    git commit -m "Deploy LexDesk"
    git push

STEP 3 — VERIFY .nojekyll uploaded
  After uploading, go to your repo root on GitHub.com and confirm
  you can see a file named ".nojekyll" listed there. GitHub hides
  dotfiles in some views — click "Show hidden files" if you don't
  see it.

STEP 4 — Wait for Pages to redeploy
  Go to Settings → Pages and wait for the green checkmark.
  Usually takes 30-90 seconds after a commit.

STEP 5 — Test
  Open: https://atharvaujoshicric-dev.github.io/Lawyer2.0/
  You should see the LexDesk login screen immediately.
  No loading errors, no 404s — everything is inside index.html.

WHY THIS VERSION WORKS
======================
Previous versions tried to load 42 separate HTML files from a
"partials/" folder at runtime using fetch(). GitHub Pages runs
Jekyll which blocks files starting with "_" (like _app-shell.html),
causing the 404 errors you kept seeing.

This version has ZERO external file loading. The entire app —
all screens, views, modals, and JavaScript — is inside the single
index.html file. It cannot 404 because there's nothing to fetch.
