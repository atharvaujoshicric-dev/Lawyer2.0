================================================================
 LEXDESK — GITHUB PAGES SETUP GUIDE (drag-and-drop method)
================================================================

This guide assumes you are NOT using git commands or a terminal —
just the GitHub website, dragging files in with your mouse. Follow
every step in order. Do not skip the ".nojekyll" step — it is the
single most common cause of a broken deploy with this method.


----------------------------------------------------------------
STEP 1 — Create the GitHub repository
----------------------------------------------------------------

1. Go to https://github.com and log in.
2. Click the "+" icon top-right, then "New repository".
3. Name it anything (e.g. "Lawyer2.0" or "lexdesk").
4. Set it to Public (GitHub Pages on a free account requires the
   repo to be public).
5. Do NOT check "Add a README file" — leave the repo completely
   empty. Click "Create repository".


----------------------------------------------------------------
STEP 2 — Show hidden files on your computer (IMPORTANT)
----------------------------------------------------------------

The project contains a file called ".nojekyll" — note the leading
dot. Files starting with a dot are "hidden files" and your computer
may not show them to you by default, which means you might drag
the project folder in and never even see this file to upload it.

WINDOWS:
  Open File Explorer → View tab (top ribbon) → tick "Hidden items".

MAC:
  Open Finder → Press Cmd + Shift + . (period) → hidden files now show
  with a slightly faded icon. Press the same shortcut again to hide
  them once you're done.

Confirm you can now see a file named exactly ".nojekyll" inside the
extracted project folder before continuing to Step 3.


----------------------------------------------------------------
STEP 3 — Extract the zip file
----------------------------------------------------------------

1. Unzip / extract the LexDesk project zip file you were given.
2. Open the extracted folder. You should see, directly inside it:
     index.html
     .nojekyll
     README.md
     assets/        (a folder)
     partials/      (a folder)
     database/      (a folder)
     docs/          (a folder)

If you only see ONE file or a single nested folder instead of this
list, you extracted into a subfolder by mistake — go one level up
or re-extract.


----------------------------------------------------------------
STEP 4 — Upload everything to GitHub
----------------------------------------------------------------

GitHub's drag-and-drop uploader can be unreliable with folders in
some browsers. Use this method, which works consistently:

1. On your new (empty) repository page on github.com, click
   "uploading an existing file" (a blue link in the middle of the
   page) — or click "Add file" → "Upload files" if you don't see
   that link.

2. A box appears saying "Drag files here to add them to your
   repository".

3. Open the extracted LexDesk folder in a SEPARATE window
   (File Explorer on Windows, Finder on Mac) so you can see all its
   contents at once: index.html, .nojekyll, README.md, assets,
   partials, database, docs.

4. SELECT ALL of those items at once (Ctrl+A on Windows, Cmd+A on
   Mac, while that folder window is focused) and drag the ENTIRE
   SELECTION onto the GitHub upload box in one motion.

   Do not drag the outer folder itself — drag its CONTENTS. If you
   drag the outer folder, everything ends up one level too deep
   (e.g. "Lawyer2.0/index.html" instead of "index.html" at the
   repo root) and the site will not work.

5. Wait — GitHub will show a list of files being processed. This
   can take 1-2 minutes for ~90 files. Do not close the tab.

6. Scroll down and CONFIRM you see ".nojekyll" listed among the
   files about to be committed. If you don't see it, go back to
   Step 2 — your file manager is still hiding it from the drag
   operation.

7. Scroll to the bottom, leave the default "Commit directly to the
   main branch" selected, and click "Commit changes".


----------------------------------------------------------------
STEP 5 — Verify the upload
----------------------------------------------------------------

After the commit finishes, you're returned to the repo's file list.
Check, by clicking into them on the GitHub website:

  [ ] .nojekyll exists at the repo root (it will show as an empty
      file — that's correct, it's supposed to be empty)
  [ ] index.html exists at the repo root
  [ ] assets folder exists, and clicking into it shows a css folder
      and a js folder with ~24 .js files inside
  [ ] partials folder exists, and clicking into it shows:
        app-shell.html  (directly inside partials, not in a subfolder)
        views   (a folder with ~21 .html files)
        modals  (a folder with 20 .html files)

If .nojekyll is missing, repeat Step 4 just for that one file:
"Add file" → "Upload files" → drag .nojekyll in by itself → commit.


----------------------------------------------------------------
STEP 6 — Turn on GitHub Pages
----------------------------------------------------------------

1. On your repo page, click "Settings" (top menu).
2. In the left sidebar, click "Pages".
3. Under "Build and deployment" → "Source", select
   "Deploy from a branch".
4. Under "Branch", choose "main" and "/ (root)", then click "Save".
5. Wait 1-2 minutes. Refresh the Settings → Pages screen until you
   see a green box: "Your site is live at
   https://<your-username>.github.io/<your-repo-name>/"


----------------------------------------------------------------
STEP 7 — Open your site and test it
----------------------------------------------------------------

1. Click the live URL from Step 6.
2. You should see the LexDesk login screen, not an error message.
3. If you see "Failed to load LexDesk" with an HTTP 404 error
   naming a specific file — that exact file is missing from your
   repo. Go back to Step 5 and check it's really there at the
   exact path the error message shows.
4. If you see a blank white page with no error at all, open your
   browser's developer console (F12, then click "Console") and
   look for red error text — copy it for troubleshooting.


----------------------------------------------------------------
STEP 8 — Confirm Supabase connection works
----------------------------------------------------------------

Your Supabase project URL and key are already saved inside
assets/js/env.js in this project — you do not need to enter them
anywhere in the app itself.

1. On the live login screen, click "Sign Up".
2. Choose "Start a new firm", fill in your name, email, password,
   and firm name.
3. Click "Create Account".
4. You should land on the Dashboard as the firm admin.

If sign-up fails with a database error, your Supabase project may
not have the schema applied yet — see database/README.md and
docs/SETUP.md (sections 2 and 3) inside this project for how to run
the SQL migration files in the Supabase dashboard's SQL Editor.


----------------------------------------------------------------
TROUBLESHOOTING QUICK REFERENCE
----------------------------------------------------------------

PROBLEM: "Failed to load LexDesk — HTTP 404 fetching .../partials/
          app-shell.html"
CAUSE:   The partials folder (or that specific file) did not
         actually get uploaded to GitHub.
FIX:     Go to your repo on github.com, click into partials/, and
         check app-shell.html is really there. If not, "Add file"
         → "Upload files" → drag it in by itself → commit.

PROBLEM: Site loads but every button does nothing / console shows
         "X is not a function"
CAUSE:   One or more files in assets/js/ failed to upload, or
         uploaded out of order somehow.
FIX:     Click into assets/js/ on github.com and count the files —
         there should be exactly 24 .js files plus a README.md,
         numbered 00 through 23 plus env.js. Re-upload any missing
         ones.

PROBLEM: Settings → Pages never shows "Your site is live"
CAUSE:   Pages takes a few minutes the first time, or the branch
         selected in Step 6 doesn't match where you committed.
FIX:     Wait 5 minutes and refresh. If still stuck, re-check Step
         6 — Branch must say "main" (or whatever your default
         branch is actually named — check the repo's main page).

PROBLEM: You dragged the whole project folder in (not its
         contents) and now everything is nested one level too deep
         (e.g. you see a "Lawyer2.0" folder inside your repo
         containing index.html, instead of index.html directly at
         the repo root)
FIX:     Delete the repo and start over from Step 1, being careful
         in Step 4 to select and drag the CONTENTS of the extracted
         folder, not the folder itself.
